# cross_verify — 외부 AI 교차검증 작업 폴더

## 목적

동일 질문(설계 검증·코드 리뷰·최적화 아이디어 도출 등)을 외부 AI(ChatGPT, Gemini, Claude Fable 등)에도
던져 Claude 자신의 결론과 독립적으로 대조한다. 단일 모델 판단 편향을 줄이는 것이 목적이다.

## 하위 폴더 구조 (필수)

작업 단위마다 `<YYMMDD>_<항목>/` 형식의 하위 폴더를 만들고 그 안에서만 작업한다
(예: `260804_fixslicing/`). 각 작업 폴더는 다음을 포함해야 한다:

| 항목 | 역할 |
|---|---|
| `QUERY_PROMPT.md` | 외부 AI에게 보낼 질의문. 아래 "프롬프트 필수 규칙" 준수 |
| `src/` | 질의문과 함께 제공할 부속 자료(소스 코드·데이터·기존 문서 발췌 등) 모음 |
| `<YYMMDD>_<항목>.zip` | `QUERY_PROMPT.md` + `src/` 전체를 압축한 파일 — 외부 AI 업로드용 |
| `<AI이름>_<항목>_ANSWER.md` | 사용자가 외부 AI로부터 받아 업로드한 답변 원본. **무수정 보존** |
| `<YYMMDD>_교차검증판정.md` | Claude 가 외부 AI 답변(들)을 교차검증하여 작성하는 최종 결론 |

## 프롬프트 필수 규칙 (필수)

`QUERY_PROMPT.md` 작성 시 답변 형식 절에 다음 두 요구를 항상 포함한다:

1. **"답변 전체를 단일 마크다운(.md) 파일 하나로 출력하라"** — 여러 파일로 쪼개진 답변은
   이 폴더의 원본 보관·교차 대조 운용 방식과 맞지 않기 때문이다.
2. **"답변 파일 이름은 `<AI이름>_<항목>_ANSWER.md` 로 하라"** (예: `CODEX_fixslicing_ANSWER.md`,
   `CHATGPT_fixslicing_ANSWER.md`, `GEMINI_fixslicing_ANSWER.md`) — `<항목>` 은 이 작업 폴더명
   `<YYMMDD>_<항목>` 의 `<항목>` 부분으로, 해당 질의 번들을 식별하는 키워드다. 여러 작업
   폴더의 답변 파일이 한곳(다운로드 폴더 등)에 모여도 `<AI이름>_ANSWER.md` 로만 겹쳐 어느
   질의에 대한 답변인지 구분이 안 되는 문제를 막기 위함이다. 위 하위 폴더 구조 표의 답변
   원본 명명과 일치시켜, 받은 파일을 개명 없이 그대로 폴더에 넣는다. 파일 첫 줄에 모델명·버전
   명기도 함께 요구한다.

## 작업 절차

1. `<YYMMDD>_<항목>/` 폴더 생성 → `QUERY_PROMPT.md` 작성(위 프롬프트 규칙 포함) → 부속 자료를
   `src/`에 모음.
2. 폴더 전체를 `<YYMMDD>_<항목>.zip`으로 압축.
3. 사용자가 `QUERY_PROMPT.md`(+ 필요 시 zip)를 외부 AI에 제공하고 답변을 받아 이 폴더에 업로드.
4. Claude 가 외부 AI 답변(들)과 자체 판단을 교차검증하여 `<YYMMDD>_교차검증판정.md` 를 작성 —
   합의·불일치 지점, 채택/기각 사유를 명시.
5. 채택된 결론은 프로젝트 권위 문서(예: `OPT.md`·`OPT_IDEA.md`·`CONTRIBUTION.md` 등 프로젝트별
   해당 문서)로 반영한다. 이 폴더의 원본·판정 파일 자체는 프로젝트 권위 문서가 아니다 — 인용
   시 반드시 승격된 권위 문서를 가리킨다.

## 원본 보존 원칙

이 폴더에 업로드된 외부 AI 답변 원본은 사후에 수정하지 않는다. 오류가 발견되면
`<YYMMDD>_교차검증판정.md` 쪽에서 정정하되, 원본 텍스트 자체는 고치지 않는다.
